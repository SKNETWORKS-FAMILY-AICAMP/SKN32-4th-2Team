## 남은 우선순위

1. `work-duty-general`: 일반 질문에 기술연구원 전용 청크를 쓰지 않도록 audience 필터 강화
2. `pay-overtime-b`: 시간외·야간·휴일근무 명칭과 표 행의 비고를 함께 구조화해 표현 혼합 방지
3. 수동 평가 run의 `verification_failed` 6건(runtime-only 반복은 5건): 수치 안전성은 유지하면서 근거가 충분한 연차·교원 임용·의료비 답변의 과잉 차단 완화
4. 5초 목표: 의미 검증·교정이 겹치는 실패 경로를 최적화하되 배포 timeout 15초는 유지

## 제한사항

- 한 PC, 한 날짜, 순차 단일 사용자 측정이며 AWS·동시성 측정이 아니다.
- 위험도는 통계적 정확도가 아니라 context 기반 정성 판정이다.
- 수동 위험도 등급은 15:25 raw에만 적용되며 15:55 runtime-only 반복에는 적용하지 않았다.
- 질문 파일과 코드가 초기 보고서 실행 시점과 달라 결과를 단순 동일조건 반복으로 보지 않는다.
- 현재 raw의 `got_sources`는 파일명·페이지만 기록해 새 `article` API 필드를 보존하지 않는다.
  조문 표시는 별도 실요청 `병가 사용 가능해?`에서 `복무규정 · 제21조(병가) · p.5`로 확인했다.
- `pay-overtime-b`는 최초 context 텍스트만 보고 치명으로 분류했으나 PDF 13쪽 표와
  질문 의미를 다시 검토했다. `야근`만으로 22~06시 야간근무를 확정할 수 없으므로
  시간외근무수당 산식 검색은 합리적이고 150% 산식도 맞다. 다만 답변의 수당 명칭과
  제외 조건 표현이 일치하지 않아 최종적으로 경미로 정정했다.
