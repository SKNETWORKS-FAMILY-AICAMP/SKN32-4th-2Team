## 2. GPU 로 돌리면 검색이 훨씬 빠릅니다

readme 에 "약 10~30초"라고 적어두신 부분인데, GPU 로 올리니 **0.55초**가 나왔습니다.
20~50배 차이라 공유드립니다.

`rag_pipeline.py` 두 곳입니다.

```python
# get_embedding_model()
model_kwargs={"device": "cpu"},        # ← 여기

# get_reranker_model()
CrossEncoder("BAAI/bge-reranker-v2-m3")  # ← device 미지정
```

GPU 가 없는 팀원 PC 도 있으니 하드코딩보다는 자동 감지를 제안드립니다.

```python
def _device() -> str:
    forced = os.getenv("RAG_DEVICE", "").strip().lower()
    if forced:
        return forced
    try:
        import torch
        return "cuda" if torch.cuda.is_available() else "cpu"
    except ImportError:
        return "cpu"
```

리랭커(`bge-reranker-v2-m3`)는 568M 파라미터라 이 파이프라인에서 가장 무겁습니다.
GPU 에서는 fp16 으로 올리면 VRAM 을 절반만 씁니다(약 2.3GB → 1.2GB).

```python
CrossEncoder("BAAI/bge-reranker-v2-m3", device=device,
             model_kwargs={"torch_dtype": torch.float16})
```

참고로 이 테스트는 RTX 4070 Laptop 8GB 에서 했고, 적재된 상태에서 3.7GB 를 씁니다.
26개 PDF 전체 적재도 GPU 에서는 **29초**에 끝났습니다.

## 4. "연차"라는 단어로만 검색이 실패합니다 ⚠

이게 가장 재현이 명확한 문제입니다. **같은 것을 묻는데 단어만 바꾸면 결과가 갈립니다.**

| 질문 | `복무규정.pdf` 검색됨? | 리랭커 점수 |
|---|---|---|
| **연차** 며칠까지 쓸 수 있나요? | ✗ | 0.0001 (사실상 무매칭) |
| **유급휴가**는 1년에 얼마나 주어지나요? | ✓ | 정상 |
| 제가 쓸 수 있는 **휴가** 일수가 궁금합니다 | ✓ | 정상 |

"연차" 질의로는 `교육공무원법`, `교육공무원임용령`, `근로기준법(시행령)`의 통상임금
계산 조항 같은 무관한 청크가 올라오고, 리랭커 점수가 전부 0.001 미만입니다.
즉 **후보 단계에서 이미 관련 문서가 안 뽑히고 있습니다**(리랭커가 걸러낸 게 아니라
리랭커에게 갈 후보 자체가 없는 것으로 보입니다).

연차 문의는 사내 HR 질문 중 가장 흔한 축이라 실사용에서 바로 드러날 것 같습니다.

BM25 한국어 정규화를 추가하신 커밋(`ad0cb60`)이 있던데, "연차"가 그 경로에서
어떻게 처리되는지 한번 봐주시면 좋겠습니다.

### 표현을 바꿔가며 6번 물어본 결과

같은 것을 묻는 문장 6개 중 **복무규정이 검색된 것은 3개뿐**이었습니다.

| 질문 | 복무규정 | 최고 점수 |
|---|---|---|
| **유급휴가**는 1년에 얼마나 주어지나요? | ✓ | 0.981 |
| 1년에 쓸 수 있는 **유급휴가** 일수는? | ✓ | 0.803 |
| 제가 쓸 수 있는 휴가 일수가 궁금합니다 | ✓ | 0.243 |
| 1년에 **휴가**가 몇일이 주어지나요? | ✗ | 0.756 |
| **휴가** 며칠 쓸 수 있어? | ✗ | 0.347 |
| **연차** 며칠까지 쓸 수 있나요? | ✗ | 0.006 |

원인이 짐작됩니다. 복무규정 제20조 원문은 **"유급휴가"** 라는 표현을 쓰고
"연차" 는 거의 쓰지 않습니다(해당 청크에서 유급휴가 3회, 연차 2회, 휴가 13회).
질문에 "유급휴가" 가 들어가야 어휘가 맞아 걸리는 것으로 보입니다.

실제 사용자는 "연차" 나 "휴가" 라고 묻지 "유급휴가" 라고 묻지 않습니다.
실제 화면에서도 이렇게 나왔습니다 — 같은 질문인데 출처가 달라집니다.

> "1년에 휴가가 몇일이 주어지나요?" → "**근로기준법**에 따르면, 1년에 15일…"
> "유급휴가는 1년에 얼마나 주어지나요?" → "**복무규정**에 따르면, 교직원에게는 1년에 15일…"

내용은 둘 다 맞습니다(복무규정이 근로기준법과 같은 기준을 정하고 있어서요).
다만 사용자 입장에서는 같은 질문에 근거가 왔다 갔다 하는 것으로 보입니다.

동의어를 질의에 확장해 주시거나(연차/휴가/유급휴가/연가), 색인 시 동의어를
함께 넣어주시면 해결될 것 같습니다.

재현 코드입니다.

```python
import httpx
for q in ["연차 며칠까지 쓸 수 있나요?", "유급휴가는 1년에 얼마나 주어지나요?"]:
    r = httpx.post("http://localhost:8001/api/search", json={"query": q}, timeout=60)
    for x in r.json()["results"]:
        print(q, "|", x["metadata"]["source_file"], x["rerank_score"])
```

## 4-1. 청크가 조문 중간부터 시작해서 조문 번호를 알 수 없습니다 ⚠

이건 답변 품질에 직접 영향을 줍니다.

"공휴일에 대한 급여는 어떻게 산정이돼?" 를 물으면 검색은 **정확히 맞는 청크**를
1위로 줍니다(근로기준법 p.13, rerank 0.296). 그런데 그 청크가 이렇게 시작합니다.

```
법제처 14 국가법령정보센터 근로기준법 1. 8시간 이내의 휴일근로: 통상임금의
100분의 50 2. 8시간을 초과한 휴일근로: 통상임금의 100분의 100 ③ 사용자는 야간근로...
```

내용은 맞지만 **"제56조" 라는 조문 머리가 없습니다.** 앞 청크에 잘려 있습니다.
그러면 저희 쪽 모델이 조문 번호를 기억으로 붙여서 이런 답이 나옵니다.

- "근로기준법 **제2항**에 명시되어 있습니다" (조 번호 없이 항만)
- "근로기준법 **제55조**에 따라" (제55조는 유급휴일 보장, 수당과 무관)
- "근로기준법 **제57조**에 따른" (제57조는 보상 휴가제, 역시 무관)

프롬프트로 "문서에 보이는 번호만 인용하라" 고 여러 방식으로 지시해 봤지만,
같은 질문을 반복하면 **1/3~1/2 확률로** 여전히 틀립니다. 컨텍스트에 정답 번호가
아예 없으니 프롬프트로는 한계가 있습니다.

**청킹할 때 각 청크 앞에 조문 머리(`제N조(제목)`)를 붙이면** 해결됩니다.

### 저희 쪽 사본에서 먼저 고쳐 봤습니다 — 패치와 측정치 첨부

말로만 요청드리기보다 직접 해보고 효과를 재는 편이 나을 것 같아, 저희가 따로
받아둔 사본(`rag_pipeline.py`)에서 고쳐 26개 문서를 다시 적재하고 측정했습니다.
**담당자님 브랜치는 건드리지 않았습니다.** 패치는 [rag_article_head.patch](rag_article_head.patch)
에 있습니다(GPU 관련 변경도 함께 들어 있습니다).

측정 결과 (LLM 벤치 35문항, GPT-4o-mini):

| 지표 | 조문 머리 없음 | 조문 머리 있음 |
|---|---|---|
| 조문 인용 횟수 | 2건 | **11건** |
| 그중 잘못된 인용 | 0건 | **0건** |
| 정답 문서 검색 성공 | 27/33 | **29/33** |
| 주제 분류 정확도 | 33/35 | 33/35 |

인용이 5배로 늘었는데 **오류는 0건 그대로**입니다. 답변에 근거가 눈에 보이게 되고
사용자가 원문을 찾아볼 수 있게 됩니다. 실제 답변도 이렇게 바뀌었습니다.

> **이전** "…통상임금의 1.5배를 지급받아야 합니다. 이는 근로기준법 **제55조**에…"
> (제55조는 유급휴일 보장 조항이라 수당과 무관합니다)
>
> **이후** "8시간 이내의 휴일 근로에 대해서는 통상임금의 100분의 50을 지급하고,
> 8시간을 초과한 경우 100분의 100을 지급해야 합니다. (근로기준법 **제56조**에 따르면)"

전체 286청크 중 조문을 알 수 없던 것이 82개 → 7개로 줄었습니다.

### 구현하며 걸렸던 두 가지

혹시 직접 구현하실 때 도움이 될까 해서 적어 둡니다.

**(1) 페이지 단위로만 보면 안 됩니다.** 조문이 페이지를 넘어 이어지면 그 페이지에
조문 머리가 하나도 없습니다. 실제로 문제의 근로기준법 p.13(휴일근로 수당)이
그런 경우로, 제56조 머리는 p.12 에 있습니다. 앞 페이지에서 이어지는 조문을
물려받게 해야 합니다.

**(2) "청크에 조문 머리가 있으면 안 붙임" 은 틀린 규칙입니다.** 저희가 처음 그렇게
했다가 문제의 청크를 그대로 놓쳤습니다. 이런 청크가 있기 때문입니다.

```
...1. 8시간 이내의 휴일근로: 통상임금의 100분의 50 ...
제57조(보상 휴가제) 사용자는 근로자대표와의 서면 합의에 따라...
```

앞부분은 제56조인데 뒤에 제57조 머리가 보입니다. 그래서 LLM 이 100분의 50 을
제57조 것으로 오해했습니다. **"조문 머리로 시작하지 않으면 붙인다"** 로 판정해야
앞부분이 어디 것인지 분명해집니다.

메타데이터로만 주셔도 됩니다(`metadata.article`). 저희가 프롬프트에 조립하겠습니다.
검색 정확도에도 도움이 될 것 같습니다 — 지금은 "제56조" 로 검색해도 그 청크가
안 잡힙니다.

덤으로, 청크 앞머리의 `법제처 14 국가법령정보센터` 는 페이지 머리말이라 내용이
아닙니다. 모든 청크에 붙어 프롬프트 토큰을 낭비하고 검색 점수도 왜곡합니다
(짧은 청크가 머리말만으로 점수를 얻습니다). 정규식 몇 줄로 걷어낼 수 있습니다.

## 4-2. 답변의 근거 부족은 **대부분 검색이 못 찾아온 것**이었습니다

답변에 근거 없는 문장이 얼마나 있는지 재는 도구를 만들었습니다
(`bench/judge.py` — 답변을 프롬프트에 들어간 근거하고만 대조). 35문항 중 16건에서
근거 없는 문장이 나왔는데, 이게 두 가지를 뭉뚱그리고 있었습니다.

- (a) 코퍼스에는 있는데 **검색이 못 찾아온** 것
- (b) 코퍼스 어디에도 없는데 **LLM 이 지어낸** 것

고쳐야 할 곳이 다르므로 갈라봤습니다(`bench/trace_claim.py` — 지적된 문장마다
28개 문서 전체를 다시 뒤져 뒷받침할 대목이 있는지 확인).

| 구분 | 건수 |
|---|---|
| 코퍼스에 있는데 검색이 못 찾아옴 | **20/23 (87%)** |
| 코퍼스 어디에도 없음 | 3/23 |

**그리고 그 3건도 실제 환각이 아니었습니다.** 2건은 "이 내용은 근로기준법
제60조에 근거합니다" 라는 출처 표기(제60조는 실제로 연차 유급휴가 조항이라
맞는 서술입니다), 1건은 "규정에서 찾을 수 없습니다" 라는 거절 문구였습니다.

즉 **지금 답변 품질을 깎는 원인은 사실상 검색 하나입니다.** 예를 들어:

| 답변이 말한 것 | 코퍼스 어디에 있었나 | 검색 결과에 |
|---|---|---|
| "1년 15일, 2년마다 1일 가산, 최대 25일" | 복무규정 p.4 제20조 | 없었음 |
| "법정 근로시간은 주 40시간" | 근로기준법 p.11 제50조 | 없었음 |
| "유연근무 신청은 부서장 승인" | 유연근무제 운영지침 p.2 제4조 | 없었음 |
| "혈중알코올농도 0.08% 미만은 정직·감봉" | 직원인사규정 시행규칙 p.51 | 없었음 |

전부 문서에 정확히 있는 내용인데 검색이 다른 청크를 가져왔습니다. 모델이 아는
내용이라 답은 맞게 나왔지만, **근거로 뒷받침되지 않은 답변**이라 언제든 틀릴 수
있습니다. 위 3·4·5번(문서 누락, "연차" 검색 실패, 동의어)이 해결되면 이 수치도
같이 좋아질 것으로 봅니다.

## 5. 사내 규정이 법령에 밀리는 경향이 있습니다

법령 문서가 청크 수로 훨씬 많다 보니, 검색 결과가 법령 위주로 채워지는 일이 잦습니다.
그런데 직원이 실제로 필요한 답은 대개 **사내 규정** 쪽입니다. 법령은 최저 기준이고
사내 규정이 그보다 유리한 경우가 많기 때문입니다.

> 예: 근로기준법 제60조는 연차 15일이 최저 기준이지만,
> 복무규정 제20조는 3년 이상 재직 시 2년마다 1일씩 가산해 **최대 25일**까지 줍니다.
> 직원에게 필요한 답은 후자입니다.

저희 쪽에서는 프롬프트에 "사내 규정 우선" 지시를 넣어 대응하고 있는데, 애초에
검색 결과에 사내 규정이 안 들어오면 방법이 없습니다.

검색 단계에서 사내 문서에 자리를 일정 비율 예약하는 방식(예: top_k 의 절반)을
고려해 보시면 어떨까 합니다. 점수에 가중치를 곱하는 것보다 결과가 예측 가능합니다.

## 6. 설치 관련 (사소함)

`RAG/requirements.txt` 로 새 환경을 만들 때 두 가지가 걸렸습니다.

**(a) 버전 핀이 서로 충돌합니다**

```
langchain==0.2.16          # 이건 langchain-core>=0.2.38 을 요구
langchain-core==0.2.16     # 그런데 여기서 0.2.16 으로 고정
```

`pip install -r requirements.txt` 가 `ResolutionImpossible` 로 실패합니다.
`langchain-core` 핀을 빼면 0.2.43 이 잡혀 정상 설치됩니다.

**(b) Python 3.13 에서는 설치가 안 됩니다**

`numpy<2` 인데 numpy 1.x 는 3.13 용 휠이 없습니다. readme 에 **Python 3.11/3.12**
라고 명시해 두시면 팀원들이 헤매지 않을 것 같습니다.
(저희는 RAG·LLM·WEB 환경을 3.11.9 로 통일했습니다)

## 7. 응답 스키마 (참고 — 저희 쪽은 이미 맞췄습니다)

`/api/search` 응답이 이전과 달라져서 저희 어댑터를 수정했습니다. 지금 형태입니다.

```jsonc
{
  "query": "...",
  "results": [{
    "doc_id": "10",                  // 문자열
    "content": "...",
    "metadata": {
      "source": "C:\\...\\res/pdf/5.근로기준법(시행령).pdf",  // 절대경로
      "source_file": "5.근로기준법(시행령).pdf",              // ← 이걸 씁니다
      "page": 1, "page_number": 1,
      "chunk_id": 8, "is_legal_text": true
    },
    "score": 0.3001, "rerank_score": 0.0001,
    "bm25_score": 1.0, "faiss_score": 0.9503
  }]
}
```

저희는 알려진 필드명을 모두 받도록 해뒀으니 앞으로 바뀌어도 대응됩니다.
다만 **`metadata.source` 는 절대경로**라 그대로 화면에 뿌리면 담당자분 PC 경로가
사용자에게 노출됩니다. 저희 쪽에서는 파일명만 잘라서 쓰고 있습니다.

관련 없는 결과까지 5건을 채워서 주시는데, 저희는 리랭커 점수를 그대로 신뢰하고
있습니다. 점수가 낮으면 아예 빼주시는 편이 나을지 의견 주시면 맞추겠습니다.
