# RAG 서비스에 요청드리는 API 명세

> **받는 사람: Member C (RAG 담당, port 8001)**
> 보내는 사람: Member D (LLM 담당, port 8002)

LLM 서비스가 답변을 만들려면 관련 문서를 검색해야 합니다.
시퀀스다이어그램(PPT 17p)의 `LLM 서비스 → 문서 저장소(RAG): 관련 문서 검색 / 문서 반환` 구간입니다.

아래는 **제가 이미 이 형태로 호출하도록 구현해 둔** 계약입니다.
다르게 만드셨거나 바꾸고 싶으시면 알려주세요. **제가 맞추겠습니다.**

---

## 필요한 엔드포인트: `POST /v1/search`

### 요청 (제가 보냅니다)

```
POST http://localhost:8001/v1/search
Content-Type: application/json
```

```json
{
  "query": "연차 며칠까지 쓸 수 있나요?",
  "top_k": 5
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `query` | string | 검색할 자연어 문장. 보통 사용자 질문 원문이고, 후속 질문일 때는 직전 질문을 앞에 붙여 보냅니다 (최대 500자) |
| `top_k` | int | 받고 싶은 청크 개수. **선택으로 만들어 주세요** — 안 보내면 그쪽 기본값(5 정도), 너무 큰 값이 오면 상한선으로 잘라주시면 됩니다 |

> `top_k` 를 제가 보내는 이유는, 받은 청크가 전부 **제 프롬프트로 들어가** 토큰 비용·응답 지연·답변 품질에 직접 영향을 주기 때문입니다.
> 성능 보고서에서 3/5/10 으로 바꿔가며 비교할 계획이라 제 쪽에서 조절할 수 있어야 합니다.

### 응답 (제가 받습니다)

```json
{
  "results": [
    {
      "doc_id": 12,
      "original_file_name": "5.근로기준법(법률).pdf",
      "content": "제60조(연차 유급휴가) ① 사용자는 1년간 80퍼센트 이상 출근한 근로자에게 15일의 유급휴가를 주어야 한다.",
      "score": 0.87,
      "page": 23
    }
  ]
}
```

| 필드 | 타입 | 필수 | 용도 |
|---|---|---|---|
| `original_file_name` | string | ✅ | **필수.** 챗봇 답변 하단 "근거 문서" 표시에 그대로 씁니다 (스토리보드 13p). `document.original_file_name` 과 같은 값이면 좋습니다 |
| `content` | string | ✅ | **필수.** LLM 프롬프트의 [참고 문서] 블록에 넣습니다. 이게 없으면 답변 근거가 없습니다 |
| `doc_id` | int | ❌ | `document.doc_id`. 있으면 프론트가 문서 원본으로 링크를 걸 수 있습니다 |
| `page` | int | ❌ | 있으면 "복무규정.pdf p.5" 형태로 표시합니다 |
| `score` | float | ❌ | 유사도. 디버깅/성능 보고서용 |
| `article` | string | ⚠ | **연동 후 추가로 요청드립니다.** `"제60조(연차 유급휴가)"` 형태. 아래 참조 |

> **`original_file_name` 과 `content` 두 개만 있으면 동작합니다.** 나머지는 없으면 `null` 로 두셔도 되고, 있으면 사용자 경험이 좋아집니다.
> 필드명이 다르면(`file_name`, `text` 등) 말씀만 해주세요. 제 쪽 `app/services/rag_client.py` 의 매핑만 바꾸면 됩니다.

### `content` 는 조문 머리부터 시작해야 합니다 ⚠

**이 문서를 처음 쓸 때 빠뜨린 요구사항입니다.** 위 예시처럼 `content` 가
`"제60조(연차 유급휴가) ① 사용자는..."` 로 시작할 거라고 당연히 가정했는데,
실제로는 청킹이 길이 단위로 자르다 보니 조문 중간에서 끊깁니다.

```
법제처 14 국가법령정보센터 근로기준법 1. 8시간 이내의 휴일근로: 통상임금의
100분의 50 2. 8시간을 초과한 휴일근로: 통상임금의 100분의 100 ③ 사용자는...
```

내용은 맞지만 **몇 조인지 알 수 없습니다.** 이게 답변 품질에 두 가지로 영향을 줍니다.

1. **조문 인용이 틀립니다.** 컨텍스트에 조 번호가 없으니 모델이 기억으로 붙입니다.
   실제로 휴일근로 수당(제56조)을 설명하며 제55조·제57조를 댔습니다.
2. **내용이 잘려 답변 근거가 사라집니다.** "유급휴가 15일" 은 제60조 ① 에 있는데,
   검색된 청크가 `"초과하는 계속 근로 연수 매 2년에 대하여..."` 로 시작해
   **"15일" 이라는 글자가 컨텍스트에 아예 없습니다.** 그러면 모델이 아는 대로
   답하게 되고, 그건 근거 있는 답변이 아닙니다.

측정치로는 답변 35건 중 15건에 근거 없는 문장이 남아 있고, 그 대부분이 이 원인입니다.
저희 쪽 프롬프트로 눌러 19건 → 15건까지 줄였지만 여기가 한계입니다.

**요청 (둘 중 편한 쪽으로)**

- (a) 청킹할 때 각 청크 앞에 조문 머리를 붙여 주세요. 조문이 길어 여러 청크로
  쪼개지면 2번째 이후 청크에도 같은 머리를 반복해 넣는 방식입니다.

  ```
  [제56조(연장·야간 및 휴일 근로)]
  1. 8시간 이내의 휴일근로: 통상임금의 100분의 50 ...
  ```

- (b) 또는 `article` 필드로 따로 주세요. 저희가 프롬프트에 조립하겠습니다.

검색 정확도에도 도움이 될 것 같습니다 — 지금은 "제56조" 로 검색해도 그 청크가
안 잡힐 겁니다.

덤으로, 청크 앞머리의 `법제처 14 국가법령정보센터` 는 페이지 머리말이라 내용이
아닙니다. 모든 청크에 붙어 프롬프트 토큰을 낭비하고 검색 점수도 왜곡합니다
(짧은 청크가 머리말만으로 점수를 얻습니다).

## 헬스체크: `GET /health`

`GET http://localhost:8001/health` 로 상태를 확인합니다.
**200~499 아무 응답이나 주시면 "살아있음"으로 봅니다.** 별도 body 형식은 필요 없습니다.
없어도 서비스는 동작하지만, 제 `/health` 가 RAG 상태를 `down` 으로 표시하게 됩니다.

## 제가 지키는 약속

- **타임아웃 3초.** 이 안에 응답이 없으면 검색을 포기합니다.
- **RAG가 죽어도 챗봇은 안 죽습니다.** 검색 실패 시 제 서비스는 500을 던지지 않고,
  문서 없이 답변을 만들어 `rag_degraded: true` 로 내려보냅니다.
  → **개발 중에 8001을 마음대로 껐다 켜셔도 됩니다.**
- **진도에 구애받지 마세요.** 저는 `RAG_MODE=mock` 으로 고정 응답을 쓰며 개발 중입니다.
  준비되시면 `RAG_MODE=live` 로 한 줄 바꿔 붙입니다.

## 연동 현황 (2026-08-03 갱신)

아래 1~4번은 **연동을 마쳐 전부 해결**됐습니다. 기록으로 남겨 둡니다.

1. ~~포트 8001 이 맞나요?~~ → 맞습니다
2. ~~경로가 `/v1/search` 가 맞나요?~~ → 실제로는 **`/api/search`** 입니다. 저희가 맞췄습니다
3. ~~응답 필드명이 위와 다른가요?~~ → 다릅니다. 아래 표대로 저희가 맞췄습니다
4. ~~청킹할 때 파일명·페이지를 메타데이터로 저장하셨나요?~~ → 하셨습니다

| 이 문서에서 요청한 것 | 실제 응답 | 저희 대응 |
|---|---|---|
| `original_file_name` | `metadata.source_file` | 매핑 완료 |
| `page` | `metadata.page_number` | 매핑 완료 |
| `doc_id` (int) | `doc_id` (문자열 `"10"`) | 형 변환 |
| `score` | `rerank_score` (+ `bm25_score`, `faiss_score`) | 리랭커 점수를 최종 관련도로 사용 |

알려진 필드명을 모두 받도록 해뒀으니 앞으로 바뀌어도 저희 쪽은 견딥니다.

**남은 요청은 위 "`content` 는 조문 머리부터 시작해야 합니다" 하나입니다.**
그 밖에 연동하며 발견한 사항은 [RAG_FEEDBACK.md](RAG_FEEDBACK.md) 에 정리했습니다.

> 참고 — 메타데이터가 왜 필요했는지. 벡터는 숫자 배열이라, 색인할 때 청크마다
> 출처를 붙여두지 않으면 나중에 "이게 어느 파일 몇 페이지였는지" 복원할 방법이
> 없습니다.

```
청크 #1247
  vector:   [0.021, -0.318, 0.774, ...]        ← 검색용
  text:     "제60조(연차 유급휴가) ① 사용자는..."  ← 저에게 content 로
  metadata: { file: "5.근로기준법(법률).pdf",     ← 저에게 original_file_name 으로
              page: 23, doc_id: 12 }
```

이게 없으면 챗봇 답변 하단의 "근거 문서" 표시(스토리보드 13p)를 만들 수 없습니다.

## 테스트용

```bash
curl -X POST http://localhost:8001/api/search \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"유급휴가는 1년에 얼마나 주어지나요?\"}"
```

> Windows 에서 한글 질의를 `curl` 로 보내면 인코딩이 깨져 `422` 가 납니다.
> 파이썬으로 보내면 정상입니다.
>
> ```python
> import httpx
> r = httpx.post("http://localhost:8001/api/search",
>                json={"query": "유급휴가는 1년에 얼마나 주어지나요?"}, timeout=60)
> for x in r.json()["results"]:
>     print(x["metadata"]["source_file"], x["rerank_score"])
> ```
