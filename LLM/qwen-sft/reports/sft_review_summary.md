## 5. 확인된 회귀·잔존 오류

- 교내 육아휴직 3년 기준 대신 일반 법률 1년 기준을 계속 우선함
- 육아휴직과 육아기 근로시간 단축의 대상 연령·기간을 혼합함
- 휴업수당 70%를 초과근무 수당으로 전이함
- 문맥에 없는 시간외 125%, 야간 150%, 휴일 200% 수치를 생성함
- 통상임금과 평균임금, 업무상 재해 특례와 일반 퇴직금을 혼동함
- `교직원`을 `교원`으로 좁히고 숙련승급 주기를 잘못 설명함
- 기간제 예외 뒤의 `이 경우`를 무기계약 효과에 잘못 연결함
- 별정직 전직 예외와 복귀 시점을 틀림
- 행동강령 금품 기준에서 `초과/이상`과 직무관련 소액 금지 구조를 왜곡함
- 개인 연차 잔액은 지어내지 않았지만 사용촉진 통보기한을 연차 소멸기한으로 생성함

## 6. 문맥 없음 자동 플래그 감사

SFT 결과는 `no_context_without_guard=9`로 기록됐지만, 9답변 모두 실제로는 “제공된 규정 문서에는 … 없습니다/확인할 수 없습니다”라는 의미의 가드를 포함했다. 사전 자동 검사가 단일 고정 문구만 인식해 발생한 **9/9 오탐**이다.

다만 자동 오탐과 실제 사실 오류는 별개다. 메뉴 질문 1건은 검색되지 않은 법률상 식사 의무를 만들었고, 개인 연차 질문 2건은 잘못된 소멸기한을 생성했다. 따라서 의미 기반 가드 검사로 수정하더라도 SFT v1의 사실성 실패 판정은 바뀌지 않는다.

## 7. 주제 분류 회귀 원인

SFT의 세 파싱 실패는 모두 모델이 유효 enum인 `인사/승진` 또는 `휴가/휴직` 대신 `인사`만 출력한 사례다. 답변 생성용 SFT 어댑터가 분류 출력 형식까지 바꾼 결과다.

아키텍처상 답변용 어댑터를 주제 분류에 그대로 적용하지 않는다. 주제 분류는 Base 모델 또는 별도 소형 분류기와 JSON Schema enum 제약으로 분리하는 것이 안전하다.

## 8. 최종 판정

SFT v1은 다음 이유로 채택하지 않는다.

1. 문서에 없는 숫자·조건·절차 생성 0건 게이트 실패
2. 고유 질문 FAIL 0건 게이트 실패(12/34)
3. 주제 분류 32/34 이상 게이트 실패(31/34)
4. 사실성 향상 폭이 2/102에 불과하고 영역별 회귀 존재
5. 직접 추론 지연 증가 및 답변 장문화

이 어댑터는 실패 실험의 재현·발표 자료로 보존하고 서비스 코드에는 연결하지 않는다.

## 9. v2를 할 경우의 설계 원칙

현재 34문항은 v1 의사결정에 사용했으므로 v2의 최종 성능 주장에는 새로운 홀드아웃 B가 필요하다.

- 답변 모델과 주제 분류 모델을 분리한다.
- 기존 홀드아웃의 문장·정답을 학습 데이터로 재사용하지 않는다.
- 사용하지 않은 문서·질문 의도로 홀드아웃 B를 먼저 고정한다.
- 300~500개 규모로 확대하고 `원칙/예외`, `할 수 있다/해야 한다`, `교원/교직원`, `초과/이상`, `이 경우` 선행조건의 대조 사례를 늘린다.
- no-context, 개인 데이터, 충돌 문서 사례 비율을 높이고 근거에 없는 숫자·부서·절차를 반드시 거절하게 한다.
- 답변을 2~4문장으로 줄이고 검색 문맥에서 직접 확인되는 조항만 사용한다.
- AI 검수 후 실제 사람이 숫자·조문·예외를 승인한다.
- LoRA 용량을 줄인 보수적 설정(r=8, attention projection 중심, 1~2 epoch, learning rate 5e-5)을 별도 사전 등록해 비교한다.
- 사실성 통과 후에만 LoRA를 병합하고 같은 로컬 Ollama 양자화 조건으로 속도를 측정한다.
